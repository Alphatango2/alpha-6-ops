# v0.13 real-flight acceptance

Use one complete MSFS 2024 flight with a freshly imported SimBrief plan. Simulator UTC must match the planned flight date and UTC departure time.

1. Start at the departure gate with the parking brake set and engines off. Connect A6OPS and confirm the assignment, aircraft type, route, gate, and preflight events.
2. Fly through pushback, taxi, takeoff, climb, cruise, descent, approach, landing, taxi-in, engine shutdown, parking brake, and block-in. Confirm the aircraft and completed route move smoothly, ETA and distance decrease, and each operational event appears once.
3. During cruise, disconnect SimConnect for at least one minute while the simulator continues. Reconnect and confirm the same flight, actual departure, phase, progress, map position, and prior event list remain intact.
4. Close A6OPS completely during cruise, reopen it, and confirm the same restored state before reconnecting. The first returning sample should resume tracking without a false clock-discontinuity event.
5. Minimize A6OPS to the tray and select its taskbar or Start-menu shortcut. Confirm the existing window returns and Task Manager shows one Alpha6OPS process.
6. Complete block-in, then review the Flight Event Log and the matching JSON/JSONL files under `%LOCALAPPDATA%\Alpha6Designs\Alpha6OPS\TestLogs` for missing, repeated, or out-of-order events.
7. Use **Clear Active Flight**. Confirm the dashboard and tracker show **No Active Flight**, while the completed flight remains in Flight History and its logs remain on disk.

Record any unexpected screen state with the simulator UTC visible and retain the generated JSON and JSONL pair for diagnosis.
