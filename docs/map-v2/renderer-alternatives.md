# Map V2 renderer alternatives — checkpoint 7.21

Research date: **2026-09-24**. Scope: architecture and selection research for the existing `.NET 10` WPF desktop application. No alternative below was installed or benchmarked by this research task. “GPU” describes a documented rendering path, not measured acceleration, frame rate, or aircraft capacity on Alpha6OPS hardware. Sources are the projects’ documentation, source, licenses, and publisher package pages.

## Recommendation

**Inference / selection judgment:** retain MapLibre GL JS in WebView2 as a leading prototype candidate, with **Esri ArcGIS Maps SDK for .NET** as the strongest documented ready-made native WPF alternative and **MapLibre Native through the community WPF wrapper** as the open-source native challenger. This is a shortlist, not evidence that the JS prototype wins. A successful isolated JS test only establishes that candidate’s feasibility; a comparative performance claim requires the same workload on competing renderers.

The decision depends on the constraint that matters most:

| Priority | Candidate to advance | Deciding risk |
| --- | --- | --- |
| Open-source styled vector maps with an existing browser map API | MapLibre GL JS + WebView2 | Browser runtime packaging, host/message boundary, focus/accessibility, context loss, actual GPU availability |
| Supported native WPF control with GIS/offline tooling | ArcGIS Maps SDK for .NET 300.1 | Windows 11 support floor, production license and data/service terms, native deployment footprint |
| Open-source native WPF with MapLibre styles | `MapLibreNative.Maui.WPF` 4.5.1 | Community wrapper lifecycle and per-frame GPU readback into a WPF bitmap; package/runtime verification |
| Simple .NET 2D map with local tiles and geometry | Mapsui 5.1.0 | Standard WPF surface is CPU raster-backed; vector-tile rendering remains experimental |
| Full globe, altitude, terrain and time-dynamic 3D become core requirements | CesiumJS | Additional globe/terrain and WebView integration scope for the current flat Operations map |

Do not choose a custom WPF/Skia map engine merely to avoid a browser: it transfers projection, tiling, label placement, world wrapping, culling, picking, resource caching and graphics recovery ownership to this application. That is an engineering-scope judgment, not a measured performance result.

## Evidence and material qualifications

### MapLibre Native is viable on Windows, but the integration choice matters

**Evidence:** Native’s main [platform table](https://maplibre.org/maplibre-native/docs/book/platforms/index.html) lists Windows and GLFW, and identifies Android/iOS as the organization’s core platforms. Its [Windows guide](https://maplibre.org/maplibre-native/docs/book/platforms/windows/index.html) permits reuse of built `mbgl-core` libraries. The main table lists Windows OpenGL but not Vulkan, while the newer FFI documentation lists both. Treat these as different published integration surfaces; pin and verify the actual binary/backend rather than generalizing either table.

**Evidence:** [Official FFI](https://maplibre.org/maplibre-native-ffi/) is pre-1.0 with an unstable ABI. It exposes map/render-session concepts, leaves window/gesture/lifecycle integration to the host, and currently excludes custom layers and shader-registry access. The [.NET installation instructions](https://maplibre.org/maplibre-native-ffi/install/) explicitly say snapshot-only, with no tagged .NET release. It would be wrong to write “MapLibre has no .NET binding”; equally, this is not a supported turnkey official WPF control.

**Evidence:** The community publisher’s [4.5.1 WPF package](https://www.nuget.org/packages/MapLibreNative.Maui.WPF/4.5.1) documents an in-tree WPF image surface and removes the former HWND-hosted path. It documents offline-region downloads and a persistent resource cache. **Inference:** this deserves a bounded native experiment if browser hosting fails a requirement. GPU rendering followed by readback is not equivalent to direct GPU composition; its transfer cost is unknown here. Native library ownership, disposal after view recreation, resize/DPI and device recovery need evidence from the chosen package, not assumptions from MapLibre core.

**Evidence:** FFI [updates](https://maplibre.org/maplibre-native-ffi/guides/update-data/) replace a GeoJSON dataset; preparation can run off the owner thread. [Hit testing](https://maplibre.org/maplibre-native-ffi/guides/query-a-map/) queries the last rendered frame on the render-session owner thread. [Offline regions](https://maplibre.org/maplibre-native-ffi/guides/work-offline/) retain the selected style’s tiles, glyphs and sprites, separate from evictable ambient cache; MBTiles is a distinct format. **Inference:** separate slow basemap/static routes from moving aircraft and explicitly bound retained trail geometry.

Native core’s [license](https://github.com/maplibre/maplibre-native/blob/main/LICENSE.md) is BSD-2-Clause. FFI’s actual [LICENSE](https://raw.githubusercontent.com/maplibre/maplibre-native-ffi/main/LICENSE) says BSD-2-Clause although its README text says BSD-3-Clause; resolve notices from the exact pinned distribution. The community wrapper declares BSD-2-Clause. [MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js/blob/main/LICENSE.txt) uses BSD-3-Clause with included third-party notices. These engine licenses do not impose a Mapbox account or token; chosen tile services may require their own credentials. Engine permission does not grant rights to third-party tiles, fonts, sprites or weather.

### Mapsui is a credible .NET map, not evidence of the requested GPU path

**Evidence:** [5.1.0](https://github.com/Mapsui/Mapsui/releases/tag/5.1.0) is the stable release shown by the official release page. Its [tagged WPF control](https://raw.githubusercontent.com/Mapsui/Mapsui/5.1.0/Mapsui.UI.Wpf/MapControl.cs) creates `SKElement`. SkiaSharp’s [SKElement implementation](https://raw.githubusercontent.com/mono/SkiaSharp/main/source/SkiaSharp.Views/SkiaSharp.Views.WPF/SKElement.cs) draws through `SKSurface.Create` over a `WriteableBitmap` back buffer. **Inference:** standard Mapsui WPF rasterizes this map surface on the CPU; WPF may subsequently composite the bitmap using hardware. This is not a claim that all Mapsui platforms or custom renderers lack GPU support.

Vector-tile rendering remains explicitly [experimental](https://mapsui.com/v5/experimental-packages/). [Partial refresh](https://mapsui.com/v5/experimental-renderer/) belongs to the experimental renderer; the standard renderer redraws the full map. Do not promise either experimental capability as a stable production contract.

The [symbol API](https://mapsui.com/v5/api/pages/Mapsui.Styles.SymbolStyle.html) provides scale and clockwise rotation. Its `RotateWithMap` text includes a WPF-renderer limitation: validate heading with a rotated map using the exact Skia-backed package instead of assuming the historical wording applies identically to today’s control. [Hit testing](https://mapsui.com/v5/api/pages/Mapsui.Rendering.IMapRenderer.html), [MBTiles sample](https://github.com/Mapsui/Mapsui/blob/main/Samples/Mapsui.Samples.Common/Maps/DataFormats/MbTilesSample.cs), and [WMS](https://mapsui.com/v5/wms/) cover selection, offline tiles and compatible weather imagery mechanisms. [MIT license](https://raw.githubusercontent.com/Mapsui/Mapsui/5.1.0/LICENSE); data rights remain separate.

### ArcGIS offers the most complete documented native WPF route

**Evidence:** The [current SDK](https://developers.arcgis.com/net/) is 300.1, released August 2026. Its [requirements](https://developers.arcgis.com/net/system-requirements/system-requirements-for-300-1/) list WPF, .NET 8.0.404 or higher, Windows 11 23H2 or higher, Server 2022/2025, x64/ARM64, DirectX 11 feature level 10 for MapView/SceneView, and VC++ redistributable 14.44.35207 minimum. Older .NET versions are deprecated ahead of the next .NET-10-only release. This fits the app’s .NET 10 direction, but the OS support policy must fit the product. Do not carry forward Windows 10/x86 support statements from 200.x.

[Custom vector styles](https://developers.arcgis.com/net/wpf/sample-code/add-vector-tiled-layer-from-custom-style/), [aircraft rotation expressions](https://developers.arcgis.com/net/wpf/sample-code/animate-3d-graphic/) and [graphics identification](https://developers.arcgis.com/net/wpf/sample-code/identify-graphics/) are documented. Its license matrix includes offline vector/raster tile package creation. **Inference:** it can represent the required route/aircraft/weather layers; no throughput ranking was established.

**Evidence:** [Production licensing](https://developers.arcgis.com/net/license-and-deployment/license-levels-and-capabilities/) is mandatory. Free Lite covers many viewing/offline capabilities, but some local-file formats require Standard; license strings and service API keys are distinct. [Lite strings allow unlimited deployment](https://developers.arcgis.com/net/license-and-deployment/use-a-license-in-your-app/), while paid deployment packs have counts and 300.x requires the corresponding license generation. Therefore “Esri always requires a paid per-seat map license” is too broad. [Deployment](https://developers.arcgis.com/net/license-and-deployment/deployment/) requires native runtime resources and Esri/data attribution; service usage and content rights still need a concrete provider decision.

### Mapbox remains a commercial alternative, including an offline option

**Evidence:** Current [GL JS documentation](https://docs.mapbox.com/mapbox-gl-js/guides/) shows 3.30.0. [Style layers](https://docs.mapbox.com/style-spec/reference/layers/) expose symbol sizing/rotation and raster layers, while [interaction handlers](https://docs.mapbox.com/mapbox-gl-js/api/handlers/) provide feature interactions and keyboard map navigation. [WMS imagery](https://docs.mapbox.com/mapbox-gl-js/example/wms/) is demonstrated.

Its [license](https://github.com/mapbox/mapbox-gl-js/blob/main/LICENSE.txt) is governed by Mapbox terms and an active account; current GL JS is not the historical BSD release. The [start guide](https://docs.mapbox.com/mapbox-gl-js/guides/get-started/use-with-cdn/) requires a public access token. [Pricing](https://docs.mapbox.com/mapbox-gl-js/guides/pricing/) counts initialization as a map load with a maximum 12-hour session; recreating a view may therefore matter commercially as well as technically. [Atlas 3](https://docs.mapbox.com/atlas/guides/) supports self-hosted and air-gapped deployments under a separate Atlas license. **Inference:** it is viable where Mapbox content/support justifies the commercial dependency; the ordinary GL JS account model must not be assumed to permit an arbitrary bundled offline dataset.

### Custom WPF/Skia and Cesium are different scope choices

**Evidence:** [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-taking-advantage-of-hardware) has hardware and software rendering paths. [Skia](https://skia.org/docs/user/api/skcanvas_creation/) supports GPU-backed surfaces but does not create the application’s OpenGL context or Vulkan device. WPF [Direct3D interop](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/wpf-and-direct3d9-interoperation) introduces surface lifecycle, screen-lock, resize and multi-adapter work. **Inference:** custom GPU rendering is technically possible, but “replace Canvas with Skia” does not demonstrate a working accelerated WPF map. Scope and long-term ownership make this the weakest default for this checkpoint.

[SkiaSharp’s MIT terms](https://raw.githubusercontent.com/mono/SkiaSharp/main/LICENSE.txt) and [Skia’s BSD terms](https://raw.githubusercontent.com/google/skia/main/LICENSE) permit distribution with notices; native transitive dependencies need their own inventory. A custom renderer needs no mapping-service token for bundled data, while any network provider retains its own access and usage rules.

**Evidence:** [CesiumJS](https://cesium.com/platform/cesiumjs/) is Apache-2.0 with globe, terrain, time-dynamic visualization and 2D mode. Its [billboard API](https://cesium.com/learn/cesiumjs/ref-doc/BillboardGraphics.html) provides pixel dimensions, rotation, scale and distance scaling. [Scene](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html) exposes WebGL context options and picking; [WMS](https://cesium.com/learn/cesiumjs/ref-doc/WebMapServiceImageryProvider.html) and [local imagery templates](https://cesium.com/learn/cesiumjs/ref-doc/UrlTemplateImageryProvider.html) support weather/local-data integration paths. **Inference:** prefer it when 3D flight visualization is a product requirement, not solely to restyle the Operations basemap. A disconnected deployment still requires local libraries/workers/assets/data and removal of unintended remote defaults.

## Accessibility, maintenance and selection gates

**Evidence:** Esri publishes [SDK accessibility guidance](https://developers.arcgis.com/net/reference/accessibility/) and links a conformance report, while retaining application responsibility for alternatives, contrast, keyboard operation and accessible names. Mapbox documents keyboard map navigation. This research found no basis to certify the finished Alpha6OPS experience for any renderer.

**Inference / application requirements:** keep flight selection, details, freshness and layer toggles available in normal accessible WPF controls; provide keyboard alternatives to map-only picking. A canvas or bitmap that looks correct is insufficient evidence of screen-reader access to its aircraft. Validate focus crossing the WebView/native map boundary, keyboard escape, contrast, reduced motion, 150%/200% DPI and screen-reader behavior with the actual host.

Maintenance differs by layer: the JS options require pinned web assets plus WebView lifecycle/security updates; Native FFI requires tracking ABI snapshots; the community WPF wrapper adds its own release and bitmap-transfer behavior; Mapsui’s stable/experimental split must be explicit; Esri has a commercial SDK lifecycle and deployment matrix; custom rendering leaves most map-engine maintenance with Alpha6OPS. These are ownership assessments, not forecasts of project abandonment.

Before selecting a production renderer, measure the same controlled workload: 1, 100, 1,000 and 10,000 synthetic aircraft; steady and burst updates; bounded long trails; repeated pan/zoom; route/airport/label density; raster weather frames; hidden/minimized operation; repeated view recreation; offline start; missing tiles; GPU/context/device loss; and DPI/monitor changes. Record frame-time percentiles, input latency, UI-thread delay, CPU/GPU/memory, startup and package size. Synthetic capacity must remain labeled separately from actual observed traffic. A renderer passes only against explicit product budgets; this research reports **no measured winner**.
