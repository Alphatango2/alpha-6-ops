## Findings and follow-up

1. **P1: Complete checkpoint could permanently strand PIREP closeout — resolved.** `FlightSessionCoordinator.Tracking.cs` previously restored an active history ID from a Complete checkpoint without promoting it. `AddTrackingEvent` can save that shape before the later EndFlightHistory/ID transfer; a crash or failed last JSON replacement makes the state durable. The final restore now validates the exact ID and reconciles the row idempotently with `TryCompleteRecoveredFlight`. Null/Interrupted rows become Complete, already Complete end times are preserved, and Invalid rows are refused. The real ActivityStopped crash and Windows replacement-denial tests establish the two requested boundaries. Read evidence: `recovery/completion-red/summary.json` (57/64 pass, seven expected failures), then `recovery/completion-green/summary.json` (64/64 pass).

2. **P2: Legacy recovery advertised an impossible PIREP action — resolved.** `FlightSessionCoordinator.cs:PublishSnapshot` now withholds PirepEligible when completed identity is absent and supplies an explicit history-review status. `SubmitPirep` retains the exact-ID requirement. Legacy state remains readable and retained, and no same-flight-number database lookup can attach it to an unrelated run. This is fail-safe compatibility, not automatic durable-identity reconstruction; a legacy record with no ID still requires a separately designed/manual reconciliation path. The three legacy assertions in the 64-check result cover eligibility, explanation and no wrong-row mutation.

3. **P2: Returning to Operations discarded the prior observed trail — resolved in source and targeted evidence.** `MapProjectionPump` now distinguishes visibility continuity from operational reset. `MapProjectionService.BreakContinuity` preserves existing bounded segments while preventing any line through the hidden interval. `map-restoration/trail-red-2/summary.json` failed the two new trail assertions; `trail-green/summary.json` passes 9/9. The previous prefix and a new separate two-point post-return segment are both asserted.

4. **P2: An in-flight old projection could enter the resumed renderer — resolved.** The earlier `MapProjectionPump` consumer checked visibility/continuity only before `projection.Project`. Hide/resume during that calculation could let its eventual Offer enter the fresh renderer mailbox and reveal stale state under the current ACK visibility version. The final `PublishIfCurrent` guard checks both generations and visibility under `producerSync`, enclosing the nonblocking Offer; this serializes final publication with hide/show and closes that timeline. The deterministic publication-boundary test uses a newer sequence with an obsolete captured visibility generation. `map-restoration/publish-race-red/summary.json` records exactly that failure (9/10); `publish-race-green/summary.json` passes 10/10. The actual delayed-ACK browser navigation test is separate evidence and does not substitute for this publication check.

5. **P2: Failed Complete reconciliation could discard the only saved exact ID — resolved.** The earlier Complete restore block cleared both identity fields before calling `TryCompleteRecoveredFlight`; an IOException followed by an ordinary checkpoint save could erase the candidate. The final implementation retains a separate `pendingCompletedFlightHistoryId` for same-assignment Complete recovery. It is persisted through the existing recovery active-ID slot but is never authority for PIREP eligibility, live event writes or row finalization. Successful reconciliation and assignment/session resets clear it. The new real SQLite `BEGIN IMMEDIATE` test allows startup/identity reads, denies completion UPDATE, forces an ApplyGates/checkpoint save, releases the lock and cold-retries to one PIREP on the original ID. `recovery/retry-red/summary.json` records three expected failures (66/69); `retry-green/summary.json` passes 69/69. Reviewer read the code and result files; the recovery agent executed the test.

All five review findings above are resolved in the reviewed source and their targeted evidence. The latest targeted counts are 69/69 recovery and 10/10 projection-pump checks. This is not certification of all final integrated suites or the remaining physical/native gates.
