## Architecture and provenance

`SimConnectSource.TerminalSensors` reads optional aircraft intent separately from generic mechanical sensors. `IShutdownIntentAdapter` normalizes aircraft-specific channels into immutable `TerminalShutdownEvidence`. `BlockInEligibilityPolicy` applies the common arrival conditions, and the existing `PhaseDetector` consumes its explicit decision with its existing three-second confirmation. There is still one lifecycle, one IN transition and one exact history identity for PIREP submission.

`EngineEvidenceTracker` is unchanged. Running/Stopping/Off, N1/N2/RPM and fuel-flow interpretation remain mechanical evidence. Mechanical Stopping can coexist with terminal Complete; no engine telemetry is forged to achieve completion.

The first enhanced adapter is deliberately restricted to the captured title **FenixA321 IAE WF SC**, with both Fenix package manifests reporting **2.4.0.4720**. The configured MSFS 2024 packages path is read from `UserCfg.opt`; no fixed Community drive path is assumed. Other titles, versions or undiscoverable installations remain limited. This is not a claim covering every Fenix aircraft or livery.

Native provenance: [complete capture analysis](7.24c-fenix-shutdown-native-20260928.md), 27 signals × 180 readings = 4,860 observations. Master 1/2 polarity is 1 ON / 0 OFF. Engine 2 master/combustion OFF at 21.20/22.20 seconds; engine 1 at 38.19/39.20 seconds. Fuel-flow decay to ≤1 lb/h occurred at 71.19/89.20 seconds respectively. Replay of all 180 groups through the adapter first confirms all-engine intent at 39.20 seconds, without looking ahead to future values.

Enhanced authority requires `L:S_ENG_MASTER_1/2` OFF and `GENERAL ENG COMBUSTION:1/2` absent for both engines, correct engine count, canonical boolean values, valid fresh independent replies and no positive starter contradiction. Positive master ON plus combustion ON must have been observed for each engine on this connection. Default zero values alone never establish support. Aircraft changes discard cached master values and qualification. Optional request failures invalidate that channel without tearing down primary telemetry.

## Capability and completion policy

| Evidence | Result |
|---|---|
| Enhanced, qualified, fresh complete cutoff/combustion coverage | Automatic terminal candidate, subject to every arrival guard |
| Limited/unsupported, valid current telemetry without positive operating evidence | Guarded manual fallback only |
| Enhanced but missing/stale/unqualified/contradictory | Invalid; neither automatic nor manual completion |
| Positive combustion/starter/valid running evidence | Completion blocked, including with missing mechanical engine count |

Both automatic and manual paths require recorded ON, TaxiIn, an accepted current assignment/session, simulator running, on-ground telemetry, valid destination proximity ≤5 NM, finite groundspeed ≥0 and <0.5 kt, parking brake SET, and no pause/slew/disconnect. Airport-catalog position is the shared authority for arrival checking, with a valid planned endpoint only as a fallback. No normal off-destination override remains.

The enhanced path uses the existing three-second phase confirmation. At normal one-second sampling, Complete/PIREP eligibility is expected about **3–4 seconds after the first fresh all-engine intent observation** (roughly **4–6 seconds after the last observed master-OFF signal** for the captured one-second combustion response). This is an expectation, not an installed measurement. Effective IN remains timestamped at the beginning of the confirmed interval. All other completion/history prerequisites must already hold; this is not a wall-clock guarantee under pause, time acceleration or missing data.

Manual fallback offers Confirm Block In after ten stable simulator seconds of valid destination parking. The command rechecks the same authoritative predicate, receipt freshness, generation, evidence identity and parked interval; UI visibility is not authority. Confirmation then follows the existing three-second phase transition. Mechanical Off or combustion absence alone never triggers automatic completion for a limited aircraft.

Freshness is at most three wall-clock seconds; existing phase continuity permits at most a fifteen-second simulator sample gap. Movement, brake release, relight/master ON, missing/invalid coverage, pause/slew, stale receipts, duplicate/reversed time, a large sample gap, connection change or restart clear pending authority. A targeted pending-Complete reset preserves the normal TaxiIn→Airborne go-around transition.

Recovery restores completed operational history but never pending manual/intent authority. A reconnect while both masters are already OFF cannot qualify enhanced intent from zeros; it remains invalid until fresh positive qualification is available. This conservative limitation is explicit and must not be bypassed by silently downgrading enhanced evidence to limited support.

## Diagnostics and replay compatibility

New telemetry journals include receipt UTC, policy version and normalized terminal evidence. Tracking records include the policy's eligibility/manual decision. These are diagnostic fields; no storage schema migration is introduced. New replay journals consume the recorded policy decisions, defaulting to denial if missing. Old journals retain their original mechanical completion semantics, with no invented master data. Historical replays therefore demonstrate historical compatibility, not native proof of the new adapter. Dedicated policy/coordinator/native-capture tests verify the new decisions.

## Adding another adapter

1. Capture the exact aircraft/package/version using independent native signal reads, including required engine count, commands, combustion, start and shutdown sequences, failure/starvation and reconnect/invalid cases. Preserve source manifests, native errors, timestamps, polarity and hashes.
2. Demonstrate each required channel is supported and independent; default/mirrored zeros are insufficient. Define freshness, qualification and contradictory evidence explicitly.
3. Implement `IShutdownIntentAdapter` behind the registry and isolate optional native requests. Return normalized evidence; do not put aircraft LVar names into the coordinator or change generic mechanical thresholds.
4. Add native-capture replay, parser, policy and real coordinator/history/PIREP tests, including every required engine for a four-engine aircraft. Complete parked installed validation before promoting its exact compatibility entry.

No PMDG, iniBuilds, A220, A380 or generic automatic shutdown support is claimed. Limited/manual behavior remains the fallback. Native parked validation of the implemented build is required; full native destination completion and active-flight recovery remain later gates. No premium UI or next checkpoint work is included.
